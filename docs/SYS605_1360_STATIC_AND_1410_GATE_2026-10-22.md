# Syscall 605: retained 13.60 handler and 14.10 ID gate

The earlier description of syscall 605 as an unrestricted process-flag OR
and GPU memory read/write syscall is unsupported by its retained 13.60
sysent target. This note uses the `kernel_text.bin` hash and capture limits
recorded in `SYS601_1360_DISPATCH_AUDIT_2026-10-22.md`.

## Retained 13.60 bytes

Sysent 605's thunk at RVA `0x265e38` jumps to RVA `0xa36b00`. That handler
reads one 32-bit syscall argument and compares it against exactly these IDs:

`0x19810000`, `0x3cc80700`, `0x78026400`, `0x78028300`, `0x78028a00`.

Other values leave the entry-initialized error `0x16` in the return register.
For a matching value, the handler calls RVA `0xae70c0` with that ID and a
pointer to a four-byte local output, then writes the output to the caller
thread's syscall return slot at `thread+0x408`. RVA `0xae70c0` forwards to
`0xae70e0`, which follows an ID/device query path. No instruction in the
bounded handler at `0xa36b00`–`0xa36b81` ORs a user bitmask into a process
flag or copies arbitrary GPU memory to/from a user pointer. The earlier
`proc+0x408` reading confused the syscall return slot with a process field.

This is a static observation of an artifact labeled 13.60, whose acquisition
authenticity has not been established. It does not prove the 14.10 handler is
identical or that all device-query side effects are known.

## Live 14.10 gate

`probes/phase17_new_vectors/112b_sys605_whitelist_gate.lua` submitted seven
single-argument calls. In
`results/phase17_new_vectors/112b_sys605_whitelist_gate_20261022_201455.txt`,
PID 192 remained alive. `0x19810000` returned `0`; zero, `0x78028a01`, and
the other four listed IDs returned `-1`. The accepted ID and rejected
neighbor are consistent with filtering, but `-1` does not distinguish an
unknown ID from a known ID whose device query failed. No kernel pointer,
arbitrary read/write, or privilege change was observed.

The old probe `112a_sys605_gpu_rw_flag_or.lua` is based on the unsupported
flag/GPU interpretation and should not be run as an exploit test without a
new 14.10 argument-layout basis.
